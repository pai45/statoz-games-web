# Vibe Basketball

Local presentation revamp over mike007jd/vibebasketball at `184a5b27ee259869744f0b32de9954ab7983c1bb` (MIT). The upstream baseline is in `vendor/vibebasketball`; `SOURCE.json` records hashes checked before every build. It includes 1v1 and a four-shooter 3-Point Contest with 1–4 local players. No host rewards or economy integration is added.

Run `npm ci --prefix vendor/vibebasketball` once after checkout, then `npm run build:vibe-basketball`. Development, production and Pages prebuilds regenerate the local bundle. Three.js stays at the source's `0.170.0` inside the isolated dependency tree. The build adapts source in memory; vendor files remain unchanged. Relative script, style, font, texture and GLB paths support subdirectory hosting. No remote assets are needed at runtime.

The host route `/play/vibe-basketball` uses the existing game launcher and login gate. The iframe owns its blacktop lobby, navigation and reload behavior. Messages validate origin, frame, protocol, game and launch session. The adapter supplies error reporting, pause/resume, audio suspension and exit; removing the iframe releases its runtime. Gameplay and UI styles stay independent of the StatOz visual system.

Touch: left analog movement joystick; right shoot button (hold/release, tap fake, block on defense); sprint plus contextual attack/defense actions. Dribble accepts a tap or directional swipe; swipe and hold for a finish. The extra arrow pad is removed. Contest mode only shows shooting. Keyboard/gamepad remain supported; the Touch toolbar button toggles the overlay. Modes, setup, money racks, CPU skip, rematches and pause are touch accessible. Controls clear on cancellation, blur and rotation. Backgrounding pauses and requires explicit resume.

Validation: `npm run test:vibe-basketball`, `npm run test:vibe-basketball:browser`, lint, typecheck, production and static builds. Build a static export with `node scripts/build-github-pages.mjs` before the browser command; its second runner serves `out` to test the actual host application. Browser evidence goes in `test-results/vibe-basketball`. The checks cover five viewport sizes, real simultaneous touch pointers, canceled input, rotation, simulated backgrounding, pause stability, both modes, subdirectory assets, source input timing, login, launch/exit, error recovery, and both upstream smoke and comprehensive contest probes against the built game. Physical iOS/Android hardware checks remain manual. See `VALIDATION.md` for the completed run.

## Character design v2

Local procedural art in `character-design.js` replaces the repeated head/headband with named hair silhouettes, visible eyes and brows, shaped faces, kit piping, wristbands/compression accessories and sneaker laces. The original skeleton, skin-weight solver, hand contacts and animation code remain unchanged. The build applies the art extension in memory; the vendor baseline is preserved. Front/back jersey marks now sit on the correct sides of the torso. The Source & credits link is removed from the pause interface; original license and attribution files remain in the source and distribution.

## Blacktop presentation / athletes v3

The v3 layer supersedes the v2 procedural body and face. Quaternius' **Universal Base Characters [Standard]** male/female bodies, eyes and brows are CC0. Their original license is verified on the author's website and retained with the shipped assets. The free itch.io download endpoint was unavailable in the build environment, so the same Standard source meshes were acquired from a pinned public mirror; acquisition URLs, the mirror revision, original-byte hashes and derived-file hashes are in `public/games/vibe-basketball/art/PROVENANCE.json`. The lobby basketball is by **Zer0_Time**, CC BY 3.0, with the required attribution and license link in `CREDITS.txt` and the embedded `LICENSES.txt`.

- `scripts/prepare-vibe-athletes.mjs` fits the licensed T-pose bodies to the original contact joints and retains 40 articulated finger joints. It resizes skin/normal/eye textures and exports self-contained GLBs. This explicit art-import step is **not** run during normal builds. `--download` reacquires the pinned character sources and credited basketball; all acquisition URLs are documented in the manifest.
- `athlete-assets.js` preloads only local files, shares immutable geometry/textures, binds the models to the existing hand/contact bones, and omits large skin normal maps on mobile Performance/Auto.
- `basketball-kit.js` supplies an original, continuous tank pattern with an open neck, armholes and shoulder bridges. Jersey names/numbers are printed in cloth UVs, not floating planes. Shorts, hair, compression accessories, wrist tape and shoes remain game-owned.
- `basketball-motion.js` recreates distance-paced running, grounded foot placement, defensive slides, hand changes, shot loading/extension, finishes, finger grip and head tracking. Root movement, actual ball attachment, shot release fractions, timing windows, RNG, AI and scoring remain upstream. These are authored procedural takes, not downloaded motion capture.
- `lobby.js`, `lobby.html` and `presentation.css` stage an actual animated 3D warmup in the existing renderer. Both mode actions, the manual, keyboard/gamepad navigation and the pause/exit protocol remain connected. The warmup respects reduced motion and host pause. Barlow Condensed is reused from the repository's existing OFL font inventory and self-hosted in this game; there are no new font packages or host theme dependencies.
- The initial desktop move-list overlay is hidden so it does not obscure half the court. Press **H** for that detailed list; the lobby manual remains available before starting.

Normal builds verify every art hash before copying the assets and preserve the upstream notices unchanged. `npm run test:vibe-basketball` includes art integrity, skin weights, finger joints, garment geometry and animation-phase tests. `npm run test:vibe-basketball:browser` begins with five-size lobby/mode, local-asset, pause, foot-contact, finger and reduced-motion checks before running the existing performance, multitouch, contest and host suites. On Linux set `VIBE_CHROMIUM=/usr/bin/chromium` for the existing browser runners. Physical-device GPU/thermal performance and audible output still require device checks.

## Mobile interface v3

Phones use a 44px score strip between Back and Pause. Mode/camera/touch settings live inside Pause. The contest progress panel is compact, and its release meter sits beside the shooting thumb with no overlap. 1v1 has one movement joystick and contextual actions: Sprint/Dribble/Spin/Shoot on attack, Sprint/Stance/Steal/Block on defense. Portrait 1v1 reserves a separate bottom control dock and resizes the renderer to the actual court surface. The portrait contest camera preserves the horizontal view inside the side fences. The host respects its visible viewport height and reserves parent safe areas outside the iframe. `node scripts/verify-vibe-mobile.mjs` measures control/HUD bounds during shooting and tests joystick-plus-dribble gestures at six sizes.

## Mobile performance

Normal phone launches now select a lightweight renderer automatically; no lite URL flag is needed. Auto bounds resolution and adapts it down if frames remain slow. Pause → Graphics offers Performance (lighter) and High (desktop effects); changing quality restarts the game. HUD updates are cached without reducing touch or simulation frequency. See `PERFORMANCE.md` for measured before/after costs, testing and physical-device limitations.
