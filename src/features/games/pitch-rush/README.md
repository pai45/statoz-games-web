# Pitch Rush

Independent arcade football adaptation of markclausing/websoccer at e3628948208c4c89c781e86068d20320169f9fe5 (MIT, Mark Clausing). Vendor bytes remain unchanged and hash-checked on build. The deterministic simulation uses a 60 Hz fixed step at 75% wall-clock speed. Synthesized audio, CPU difficulty, keyboard/gamepad/touch inputs, formations and local two-player mode are retained.

Artwork uses the [Kenney Sports Pack](https://kenney.nl/assets/sports-pack), CC0. Original selected files and license are retained in vendor/kenney-sports-pack; public/games/pitch-rush/sports-art.json records hashes, atlas rectangles, pivots, alpha bounds and keeper recolours. The renderer assembles top-down bodies and limbs with distance-driven running, heading rotation, kick and slide poses. Pitch geometry, collisions and camera follow stay on the existing simulation coordinates.

Both text-free covers use the same deterministic Kenney composition. Reproduce the atlas and covers with `python scripts/import-pitch-rush-art.py path/to/kenney_sports-pack.zip` (Pillow required). Cover provenance: public/games/pitch-rush/cover-source.json. No real teams, athletes or endorsements.

The cream/blue/red interface is game-owned. Runtime artwork is embedded in the offline bundle and decoded before inputs, rendering or ready signaling begin. A failed decode offers retry/exit; disposal during loading prevents initialization. Badges and trophies are original SVG/Canvas graphics. Earned kits use cached, cloth-only recolours of the retained Kenney atlas; its source bytes and provenance stay unchanged.

Launch /play/pitch-rush from the football library. Uses the existing BundledGame host, versioned offline manifest, guest/account-scoped local saves, validated bridge and mobile landscape viewport. Rewards are game-local cosmetics and trophies, with no host currency or economy effects. The bundle can be reviewed through the existing Flutter import workflow; this change does not import it into Flutter.

## Lobby, training and career

The lobby opens before onboarding and offers Career, Quick Match, Training, Settings and Exit. First kick-off offers a skippable three-drill tutorial, then continues the selected match. Passing requires movement and two actual received short passes; defending requires a slide and recovery; scoring requires a charged shot and actual goal. The receiving player is held in place, a tackled attacker leaves time for recovery, and the practice keeper stays on the goal line with a corner open. These accommodations apply only in training. Individual drills and the full tutorial are replayable; interruptions before completion keep the first-match offer available.

Career is Rush FC's four-division climb: Local (Easy), Regional (interpolated Easy/Normal), National (Normal), Premier (Hard). Every season has six fictional clubs, five rounds, and fifteen fixtures. The player plays five matches; other results are generated once from a seeded RNG per round. Win/draw/loss points are 3/1/0; sorting uses points, goal difference, goals scored and stable club ID. Top two go up; others stay. First place earns a division trophy, promotion unlocks the next kit/badge, and a Premier title unlocks Champion cosmetics. Premier seasons remain replayable. Quick Match retains separate difficulty, duration, formations, high scores and local two-player support.

Pure rules live in `career.mjs`, drill setup/outcome detection in `tutorial.mjs`, and validation/checkpoints in `progress.mjs`. `journey.js` owns the screen/session state and DOM. The build adapter hooks before and after each simulation step, and bypasses arcade high-score prompts for career/training. Screens, pause controls and tutorial completion support keyboard and menu gamepad navigation; the small-screen career views fit without page scrolling.

## Persistence

`statoz.pitch-rush.progress.v1` is a version-1 JSON record inside the existing host's game/account storage envelope; no host protocol or schema migration is needed. It contains tutorial status/completed drills, career results/unlocks/equipment, and one active fixture snapshot. Existing `websoccer.*` settings/high scores are preserved. A `.backup` record retains the last valid write, and an unreadable original is preserved under `.unreadable` before replacement. Save failures show a persistent Retry save control, including during play.

Career checkpoints include the complete serializable simulation, formations, score, timers, RNG and AI state. They are captured every five wall-clock seconds, at goals/halftime, on pause/backgrounding, and before leaving/disposal. Continue first shows a saved-match Resume prompt. Restoration clears event queues, held input and pending charged actions; everything else resumes from the checkpoint. Full-time applies fixture results, other scores, standings and rewards in one write and clears the snapshot; fixture IDs prevent duplicate application. One slot is maintained per existing guest/account scope. Browser/OS termination can restore only the last checkpoint, not unsaved intervening frames.

Online mode is disabled in this offline edition. No upstream public relay, shared scores, Discord service or hosted integration is contacted. CPU and local two-player matches work without a server. Two-player mode requires a keyboard or gamepads; touch controls drive player one.

Build: npm run build:pitch-rush. Checks: npm run test:pitch-rush, npm run test:pitch-rush:art, npm run test:pitch-rush:aim, npm run test:pitch-rush:browser, targeted lint, typecheck and production build. Physical mobile devices, gamepads and audible output require manual acceptance testing.

The selected build also refreshes only Pitch Rush's download hash/size in asset manifests referenced by the current compiled host; historical manifests and other games' records remain unchanged. No host rebuild is needed. The browser command runs the career/tutorial suite followed by the maintained host integration suite. Career browser evidence is in `test-results/pitch-rush/career`; controlled final scores exercise the season UI, while pure simulation tests cover real drill outcomes and deterministic checkpoint continuations. The host suite limits its actual download manifest to Pitch Rush and its cover while retaining the real hashes, so the selected game can be verified against an existing host build without rebuilding unrelated games.
